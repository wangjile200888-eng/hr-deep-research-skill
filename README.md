# HR Deep Research Skill

一个面向人力资源深度研究的 Codex Skill，用于系统研究 HR、HRD、组织能力、组织诊断、人才、绩效、薪酬、激励、文化、干部梯队、员工关系、人力资源知识图谱等议题。

它不是简单的 HR 概念库，而是一套用于把人力资源研究纳入“经营问题、组织机制、方法工具、实践难点、风险控制”的结构化工作流。核心包括三部分：

1. **分析框架**：从价值链出发，推导关键组织能力，再进一步推导组织形式与组织机制、关键岗位与核心人才，最后输出招聘配置、培训发展、绩效管理、薪酬激励、员工关系、组织发展/文化等 HR 六大模块机制。
2. **方法论与工具**：使用头部咨询公司和成熟管理实践中的方法论工具，解决分析框架如何落地的问题，例如价值链分析、组织能力地图、Target Operating Model、RACI/RAPID、关键岗位识别、人才盘点、KPI/BSC/OKR、激励有效性分析等。
3. **实践与问题**：关注框架和工具在真实组织中可能遇到的阻力与解决方案，例如业务方不认同、组织能力虚化、组织形式选错、权责不清、关键岗位泛化、数据口径争议、变革落地受阻等。

## 核心方法论

这个 skill 的核心不是“收集 HR 知识点”，而是把人力资源研究拆成三层：

```text
一、分析框架
二、方法论与工具
三、实践与问题
```

### 一、分析框架

分析框架用于回答：**HR 议题到底如何从业务价值传导到组织与人力资源机制？**

默认链条是：

```text
价值链
-> 关键组织能力
-> 组织形式与组织机制
-> 关键岗位与核心人才
-> HR 机制输出（六大模块）
```

这条链路用于避免 HR 研究直接从业务问题跳到工具清单。每一层要回答的问题不同：

| 层次 | 核心问题 | 研究重点 |
|---|---|---|
| 价值链 | 企业在哪里创造价值、转化价值、交付价值、损失价值？ | 收入、利润、现金流、客户体验、效率、风险 |
| 关键组织能力 | 为了承接价值链，组织必须持续具备什么能力？ | 增长能力、复制能力、协同能力、创新能力、成本控制能力、客户运营能力 |
| 组织形式与组织机制 | 这些能力需要什么组织形态和运行机制承接？ | 职能制、事业部制、矩阵制、项目制、区域制、中台、共享服务、敏捷小队；以及权责、决策、协同、预算、例会、问责机制 |
| 关键岗位与核心人才 | 哪些岗位和人才真正承载这些组织能力？ | 关键岗位识别、核心人才画像、干部梯队、继任、人才池 |
| HR 机制输出 | HR 如何通过机制把组织能力固化下来？ | 招聘配置、培训发展、绩效管理、薪酬激励、员工关系、组织发展/文化等六大模块 |

这里的重点是：**HR 机制不是起点，而是组织能力和组织形式推导出来的结果。**

例如研究“项目工作的人力资源管理”时，不应直接讨论项目奖金或项目绩效，而应先判断：

```text
项目工作在价值链中解决什么问题？
它要求组织具备什么能力？
这种能力需要项目制、矩阵制还是敏捷小队承接？
哪些关键岗位和人才决定项目成功？
最后才设计招聘、绩效、薪酬、激励、培养和组织发展机制。
```

### 二、方法论与工具

方法论与工具用于回答：**如何把上述分析框架落到可诊断、可设计、可执行的工作中？**

这个 skill 鼓励优先使用头部咨询公司和成熟管理实践中的工具，而不是只写概念。工具必须服务于框架中的某一环。

| 框架环节 | 可使用的方法论与工具 | 解决的问题 |
|---|---|---|
| 价值链 | 价值链分析、商业模式拆解、利润模型分析、客户旅程分析 | 找到业务价值创造和损失的位置 |
| 关键组织能力 | 组织能力地图、组织健康诊断、能力差距分析、战略能力分解 | 判断组织必须建设什么能力 |
| 组织形式与组织机制 | Target Operating Model、RACI/RAPID、组织层级与跨度分析、治理机制设计、敏捷组织模型 | 设计权责、决策、协同和资源配置机制 |
| 关键岗位与核心人才 | 关键岗位识别、岗位价值评估、人才盘点、九宫格、能力模型、成功画像 | 找出承载组织能力的关键岗位和核心人才 |
| HR 机制输出 | KPI/BSC/OKR、薪酬结构设计、激励有效性分析、人才发展体系、继任计划、员工关系风险评估 | 把组织能力固化为 HR 制度和管理动作 |

使用工具时必须说明：

- 为什么选这个工具
- 它解决框架中的哪一环问题
- 需要什么输入数据
- 操作步骤是什么
- 输出什么结果
- 支持什么管理决策
- 可能被如何误用

### 三、实践与问题

实践与问题用于回答：**框架和工具落地时会遇到什么真实阻力，以及如何解决？**

HR 研究不能只停留在模型层面，还要写清楚实践中的问题：

| 实践问题 | 常见表现 | 解决方向 |
|---|---|---|
| 业务方不认同 HR 诊断 | 认为 HR 不懂业务，只会套模型 | 从价值链和经营指标切入，用业务数据证明问题 |
| 组织能力说不清 | 把能力写成口号，如“协同能力”“创新能力” | 转成可观察行为、流程、岗位和指标 |
| 组织形式选错 | 盲目上事业部、中台、项目制或矩阵制 | 先判断价值链复杂度和组织能力需求，再选组织形式 |
| 权责机制不清 | 有责任没权力，有权力不承担结果 | 用 RACI/RAPID、授权表、例会机制和问责机制澄清 |
| 关键岗位识别泛化 | 所有管理岗都被说成关键岗位 | 按业务影响、稀缺性、替代成本、风险暴露度筛选 |
| HR 机制和组织能力脱节 | 招聘、绩效、薪酬、培训各做各的 | 让六大模块围绕同一组组织能力和关键岗位联动 |
| 数据口径争议 | 人效、绩效、成本、流失率各部门口径不同 | 先统一指标定义、数据来源和使用场景 |
| 变革落地受阻 | 干部表态支持，实际不执行 | 建立试点、沟通、利益调整、节奏控制和复盘机制 |

这一部分的输出要尽量具体，包括：

- 真实业务场景
- 相关角色和利益关系
- 冲突点
- 数据口径争议
- 会议和沟通机制
- 解决动作顺序
- 风险控制方式
- 最终沉淀成什么制度、流程、模板、指标或人才机制

## 安装方式

将整个 `hr-deep-research-skill` 文件夹复制到 Codex skills 目录，并确保文件夹名为 `hr-deep-research`：

```text
~/.codex/skills/hr-deep-research/
```

Windows 示例：

```text
%USERPROFILE%\.codex\skills\hr-deep-research\
```

重启或刷新 Codex 后，即可通过 `$hr-deep-research` 使用。

使用 $hr-deep-research，深度研究项目工作的人力资源管理

## 输出特点

这个 skill 会要求研究输出具备：

- 经营问题定义
- 价值链分析
- 关键组织能力识别
- 组织形式与组织机制设计
- 关键岗位与核心人才映射
- HR 机制输出（招聘配置、培训发展、绩效管理、薪酬激励、员工关系、组织发展/文化）
- 头部咨询公司常用方法论工具
- 数据证据与判断口径
- 实践问题、阻力和风险控制
- 低水平做法 vs 高质量做法
